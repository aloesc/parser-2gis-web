# Обход всех компаний города и статистика по нишам

## Цель и контекст
Сейчас парсер работает только по готовому URL выдачи (запрос + город). Нужен режим «весь город» без текстового запроса, дополнительные колонки о сайте и нише, и сводная статистика (доля компаний без сайта по нишам).

## Границы
Входит: обход города по листовым рубрикам, дедуп по id, чекпоинты, колонки «Есть сайт» / «Рубрика верхнего уровня», сводка по нишам.
Не входит: разбиение больших рубрик по районам, проверка живости сайтов, объединение филиалов сети, статистика в GUI.

## Техническое решение
- CLI: `--city <код>` (несколько значений) вместо `-i`; старый режим `-i` сохраняется. GUI: пустое поле «Запрос» в генераторе ссылок = обход по рубрикам.
- Обход: для каждого города перебираются листовые рубрики из `parser_2gis/data/rubrics.json` (список редактируемый); для каждой формируется URL выдачи (формат уточняется отчётом site-analyzer) и используется существующий `MainParser`.
- Дедуп по id записи API между рубриками и между запусками.
- Чекпоинт: файл рядом с результатом (пройденные рубрики/страницы), повторный запуск продолжает.
- Writer: колонка «Есть сайт» (только контакт типа `website`, рядом ссылка), «Рубрики» всегда включены в этом режиме, «Рубрика верхнего уровня» по родителям из `rubrics.json`. Подтверждено на реальном сайте: выдача по рубрике открывается по `/<город>/search/<любой slug>/rubricId/<code>`, код = ключ `rubrics.json`; `MainParser` подходит без изменений.
- Статистика: считается по ЛИСТОВОЙ рубрике (напр. «Частные стоматологии», а не «Больницы»), рядом колонка «Группа» (родитель); компания с несколькими рубриками учитывается в каждой. Отдельный лист XLSX / файл CSV/JSON: рубрика, группа, всего, без сайта, доля без сайта; сортировка по доле.

## Крайние случаи
Лимит глубины выдачи 2GIS и антибот-редирект после страницы 5; рубрики, не упирающиеся в лимит, vs упирающиеся (помечаются «возможно неполные»); пустые рубрики (404); записи без рубрик; компании в нескольких рубриках; падение Chrome посреди обхода.

## Допущения
Филиалы — отдельные строки; живость сайта не проверяется; статистика считается по собранным данным.

## Проверка
Интеграционный тест по небольшому городу и 1–2 рубрикам; юнит-тесты на признак сайта, вычисление верхней рубрики, дедуп, расчёт статистики, возобновление по чекпоинту.

## Этапы
1. Анализ сайта (site-analyzer): URL выдачи по рубрике, лимиты, защита.
2. Writer-колонки и модуль статистики (независимо от п.1).
3. Обход по рубрикам, дедуп, чекпоинты, CLI/GUI (после п.1).
4. Тесты и интеграция.

## Открытые вопросы
Реальный лимит глубины выдачи на крупной рубрике не проверен. Соответствие `Rubric.id` из API ключам `rubrics.json` не проверено. Очистка utm-меток в ссылках сайтов — решить.
Капча: парсер её не решает; при редиректе на captcha.2gis.ru должен остановиться с сообщением.

## Web UI (локальный веб-интерфейс)

Запуск: `parser-2gis --web [--port 8765] [--no-browser]`. Python stdlib (`ThreadingHTTPServer`), без новых зависимостей; статика (HTML/CSS/JS, без CDN и сборщиков) в `parser_2gis/web/static/`; серверный код в `parser_2gis/web/`. Слушает только 127.0.0.1. Десктопный GUI не удаляется.

Безопасность: токен генерируется при старте и вставляется в `index.html` (`<meta name="token">`); все POST/PUT требуют заголовок `X-Token`; запросы с чужим Host/Origin отклоняются (403). Путь результата — серверный, пишется только по явному `output_path`.

### API-контракт (JSON, UTF-8)
- `GET /` → index.html; `GET /static/<file>`.
- `GET /api/bootstrap` → `{version, default_output_path, countries:[{code,name}], cities:[{name,code,domain,country_code}], config:{chrome:{...},parser:{...},writer:{...}}}` (config = текущая пользовательская Configuration без log/path).
- `GET /api/rubrics` → объект как в `rubrics.json` (`{code:{label,code,parentCode,children,isRussian,isNonRussian}}`).
- `PUT /api/config` тело = как `config` выше (частичное) → 200 `{config}` либо 422 `{errors:{путь:сообщение}}`; сохраняется в пользовательский конфиг.
- `POST /api/jobs` тело `{mode:"urls"|"crawl", urls:[str], query:str, cities:[code], rubric_code:str|null, output_path:str, format:"csv"|"xlsx"|"json", resume:bool}`. mode=urls: если `urls` пуст, но есть `query` и `cities`, URL генерируются как в desktop-генераторе. mode=crawl: `cities` + опционально `rubric_code` (узел или лист; обходятся листья). → 201 `{id}`; 409 если уже идёт задача; 422 при ошибках валидации.
- `GET /api/jobs/current` → `{id|null, state:"idle"|"running"|"stopping"|"done"|"error"|"captcha", mode, output_path, format, started_at, finished_at, progress:{done,total,records}, message, stats_available:bool}`.
- `POST /api/jobs/current/stop` → 202.
- `GET /api/events` — Server-Sent Events: `event: log` `data:{ts,level,message}`; `event: status` `data:<как jobs/current>`. При подключении сначала отдаётся текущий status и последние ~200 строк лога.
- `GET /api/stats` → `{rows:[{rubric,group,total,without_site,share}], path}` по текущей/последней задаче crawl (читает `<output>.stats.csv`), 404 если нет.
- Ошибки: `{error:"текст по-русски"}`.
